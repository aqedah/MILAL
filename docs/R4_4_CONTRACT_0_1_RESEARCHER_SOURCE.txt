==================================================
2. 핵심 설계 원칙
==================================================

R4.4 input contract는 반드시 다음을 허용해야 한다.

A. PARTIAL TEXTUAL HIERARCHY

모든 textual node가 direct parent를 가질 필요가 없다.

허용 상태:
- explicit CHILD_OF
- HIERARCHICALLY_ABOVE
- CONTINUES_WITHIN
- no direct parent assigned
- historical parent UNRESOLVED
- direct parent not required

금지:
- parent가 없으면 JOB_BOOK에 자동 부착
- nearest-opening parent
- nearest preceding unit parent
- composition group을 parent로 사용

--------------------------------------------------
B. TEXTUAL SAME-LEVEL RELATIONS

예:
- SAME_LEVEL_SIBLING

이는 parentage와 별개이다.

A ↔ B same-level
≠
A and B must share an explicitly represented direct parent

R4.4 contract가 이 관계를 독립적으로 보존해야 한다.

--------------------------------------------------
C. COMPOSITION / GROUPING

다음과 같은 non-textual group을 losslessly 보존해야 한다.

예:
- OPENING_NARRATIVE_COMPLEX
- JOB_FRIENDS_DISPUTE_COMPLEX
- CYCLE_1 / CYCLE_2 / CYCLE_3
- DIALOGUE_CYCLE_SEQUENCE
- POST_DIALOGUE_JOB
- ELIHU_SPEECH_SEQUENCE
- YHWH_JOB_RESPONSE_COMPLEX_1
- YHWH_JOB_RESPONSE_COMPLEX_2
- YHWH_JOB_RESPONSE_SEQUENCE
- FINAL_NARRATIVE_COMPLEX

중요:
GROUP_MEMBER_OF
COMPOSITION_PEER
ORDERED_MEMBER
등은 textual CHILD_OF와 별개이다.

contract는 group node와 textual node를 type-level에서 구별해야 한다.

--------------------------------------------------
D. TRANSITION

예:
- POST_CLOSURE_TRANSITION
- POST_SPEECH_NARRATIVE_TRANSITION

transition relation은:
- parentage 아님
- composition membership 아님
- overlay와도 구별

독립 relation layer로 보존한다.

--------------------------------------------------
E. OVERLAY / RESPONSIO

예:
- CONTRASTIVE_ANA_FRAME
- ELIHU_RESPONSE_ROLE_INTERVENTION
- LONG_DISTANCE_RESPONSE candidate (UNRESOLVED)

overlay는:
- span을 가로지를 수 있음
- textual hierarchy를 바꾸지 않음
- accepted / unresolved / deferred 상태를 가질 수 있음

향후 participant arc도 이 layer 또는 별도 participant-overlay layer에
추가될 수 있어야 한다.

--------------------------------------------------
F. NEGATIVE CONSTRAINT

다음을 first-class relation/state로 보존한다.

예:
- NO_DIRECT_PARENTAGE
- NO_DIRECT_RESPONSE_ANTECEDENT
- NOT_WITHIN_SECOND_TESTING_SCENE
- NOT_MEMBER_OF_CYCLE_1
- NO_BOUNDARY

중요:
“edge 없음”과
“human-adjudicated negative constraint”는 다르다.

contract에서 반드시 구별한다.

--------------------------------------------------
G. UNRESOLVED / DEFERRED

최소 다음을 구별한다.

1. historical parent = UNRESOLVED
2. human necessity says parent not required
3. live unresolved analytical candidate
4. HUMAN_DEFERRED candidate
5. UNREVIEWED future research scope

이들을 하나의 NULL로 합치지 않는다.

==================================================
14. precedence / conflict rules
==================================================

Contract는 같은 locus에 historical + later judgment가 있을 때
어떻게 소비할지 정의해야 한다.

예:
historical:
direct_parent = UNRESOLVED

later:
direct parent not required

이 경우 historical value를 삭제하지 않는다.

권장 conceptual rule:

PRESERVE_HISTORY
+
USE_LATEST_APPLICABLE_HUMAN_DECISION_FOR_ACTIVE_REPRESENTATION

그러나 exact implementation은
현재 repo architecture와 맞게 제안한다.

다음 상황도 다룬다.

- historical candidate → accepted later
- historical candidate → human deferred
- old unresolved → necessity not required
- existing positive edge + later negative edge in different dimension

다른 dimension이면 conflict로 오판하지 않는다.

==================================================
15. graph invariants proposal
==================================================

R4.4가 향후 검증해야 할 invariant를 제안한다.

최소:

I1.
No fabricated/default textual parent.

I2.
No composition group used as textual parent unless separately
human-adjudicated as a textual node, which current frozen groups are not.

I3.
No analytical relation inferred from technical navigation.

I4.
Negative constraints and absence of relation are distinct.

I5.
Same-level relation does not require explicit common parent.

I6.
Historical unresolved parent and parent-not-required may coexist.

I7.
No layer collapse.

I8.
Every active accepted relation has provenance.

I9.
Role alias cannot silently become a second textual unit.

I10.
Future overlays can be appended without modifying frozen lower layers.

I11.
Graph cycles are evaluated per relation layer,
not across all heterogeneous relation types indiscriminately.

이 마지막 항목은 특히 중요하다.

예:
bidirectional SAME_LEVEL_SIBLING은
전체 graph를 directed-tree cycle 검사하면 cycle처럼 보이지만
오류가 아니다.

따라서 cycle validation도 relation layer별 의미에 따라 수행해야 한다.
