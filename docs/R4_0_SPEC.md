## Candidate and anchor conventions

These are review conventions, not claims that marker=boundary, boundary=macro
boundary, adjacency=continuity, continuity=parentage, rarity=significance or
human CLEAR=universal rule.

- MR1 CSF and positive Wayhi: marker start atom. Explicit closure: marker end
  atom. The complete event clause/atom span remains intact in the marker table.
- Formal repeated occurrences: both explicitly supplied window endpoints. This
  inventories the positions where formal evidence begins/ends; it does not infer
  a transition from pattern presence. All accepted repeated occurrences remain,
  including low-resolution patterns. Density is reported rather than pruned.
- HR1 boundary cases: exact case plus supplied boundary_ref. HR1 adjudicates a
  verse, not a specific atom. Every native atom in that exact verse participates
  as a possible review anchor, with VERSE_SCOPE_NOT_ATOM_ADJUDICATED. No atom is
  guessed as the final boundary. All participating panel unit IDs are retained.
- Candidates group triggers only by identical native anchor atom. Event IDs and
  every source locator remain distinct; repeated display does not erase evidence.
- Singleton uniqueness alone never produces a candidate. Singleton source IDs
  and locators are retained separately. Human non-boundary case assessments are
  preserved with their exact source links, not generalized to every occurrence.

Marker human links describe co-location with an exact reviewed case scope, not
an adjudication of that marker. Candidate human status lists case-scoped original
values; empty means no linked human case, never an inferred judgment.

## Proximity and transition overlays

Adjacent-candidate relations retain all event IDs on both anchors. Distances
are differences in actual full-book atom/verse order, with same-verse and direct
adjacency flags. There is no continuity or parentage field.

Transition zones are bounded forward windows: for each candidate anchor include
every subsequent candidate at native index distance <= zone_span_atoms (default
8), requiring at least two candidate anchors and two distinct source events.
Keep every eligible window, including overlaps. This positional display width
is an explicit review parameter, not a linguistic threshold. No transitive
chain-merging, hierarchy units, parents, ranks, scores or convenience pruning.
All candidate/event IDs remain in the overlay. Highly dense formal patterns can
produce broad coverage; this is not evidence for thousands of macro boundaries.

## Validation and stop rules

Syntax, prior full regression, stage tests and inspected synthetic self-test
precede real execution. Every computed gate has a negative mutation. Gates check
source acceptance/integrity, full scope, native counts, lossless marker/formal
identity, no negative/rarity/control promotion, exact human fields/dependencies,
both continuity/addressee cautions, distinct events, overlay-only zones, forbidden
derived fields, full-book-derived focus, source hashes, exact links and replay.
The output manifest gate is computed from serialized bytes, then the final
manifest is re-sealed and verified after disk/ZIP publication.

Two fresh real processes must reproduce every member and deterministic ZIP byte.
Inputs are rehashed before publication. Any source hash/schema ambiguity,
unresolved explicit ID, semantics/human mutation, untriggered candidate,
hierarchy field or nondeterminism stops execution; no ad-hoc repair of historical
data. Gates are technical checks, not methodological acceptance of boundaries.
