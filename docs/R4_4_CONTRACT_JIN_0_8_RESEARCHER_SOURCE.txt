within a larger heterogeneous representation.

--------------------------------------------------
R2 — Jin single-mother principle
--------------------------------------------------

ACCEPTED

Jin’s single-mother invariant applies to:

STRICT_HYPOTACTIC_DAUGHTER

Rule:

IF
relation placement has been human-adjudicated as
STRICT_HYPOTACTIC_DAUGHTER

THEN
exactly one direct strict textual mother is required.

This rule does NOT apply automatically to:

- every textual node
- strict paratactic clauses
- macro units
- composition groups
- transition anchors
- overlays
- technical nodes

Important:

EVERY STRICT HYPOTACTIC DAUGHTER HAS ONE MOTHER = TRUE

EVERY TEXTUAL NODE HAS ONE MOTHER = FALSE

--------------------------------------------------
R3 — Macro mother requirement
--------------------------------------------------

ACCEPTED with qualification

Not every macro textual unit requires a direct macro mother.

Allowed macro placement modes include:

- MACRO_HYPOTACTIC_DAUGHTER
- MACRO_PARATACTIC_UNIT
- MACRO_TOP_LEVEL / ROOT_CANDIDATE
- MACRO_TRANSITIONAL_PLACEMENT
- MACRO_PLACEMENT_UNRESOLVED

Rule:

IF
a macro textual unit is human-adjudicated as
MACRO_HYPOTACTIC_DAUGHTER

THEN
exactly one direct macro mother is required.

Do NOT assign a mother merely to complete a tree.

MACRO_PARATACTIC,
MACRO_TOP_LEVEL,
and
MACRO_TRANSITIONAL_PLACEMENT

do not require synthetic mothers.

--------------------------------------------------
R4 — Historical unresolved vs macro resolution
--------------------------------------------------

ACCEPTED

Historical strict-parent states and later macro relations
must coexist independently.

Examples:

UNRESOLVED

AND

macro relation =
ACCEPTED

is valid.

Macro resolution does NOT silently resolve strict clause parentage.

Strict unresolved questions remain preserved until separately adjudicated.

Historical records are never overwritten.

--------------------------------------------------
R5 — Non-textual composition groups
--------------------------------------------------

ACCEPTED

NON_TEXTUAL composition groups remain outside both:

- STRICT_CLAUSE mother-daughter hierarchy
- MACRO_TEXTUAL mother-daughter hierarchy

Examples include:

- OPENING_NARRATIVE_COMPLEX
- JOB_FRIENDS_DISPUTE_COMPLEX
- DIALOGUE_CYCLE_SEQUENCE
- POST_DIALOGUE_JOB
- ELIHU_SPEECH_SEQUENCE
- YHWH_JOB_RESPONSE_COMPLEX_1
- YHWH_JOB_RESPONSE_COMPLEX_2
- YHWH_JOB_RESPONSE_SEQUENCE
- FINAL_NARRATIVE_COMPLEX

They may provide:

- scope
- membership
- ordering
- context evidence

but cannot serve as textual mothers.

Future retyping from NON_TEXTUAL to TEXTUAL requires
a separate versioned human adjudication.

--------------------------------------------------
R6 — Technical navigation
--------------------------------------------------

ACCEPTED

TECHNICAL_NAVIGATION is separate from analytical relations.

Technical root / navigation edges:

- are implementation/navigation aids
- are not textual hierarchy
- are not composition
- are not transition
- are not overlay
- cannot serve as mother edges

JOB_BOOK technical root must never be used
to attach otherwise parentless textual nodes.

--------------------------------------------------
R7 — Negative constraints
--------------------------------------------------

ACCEPTED

Human-adjudicated negative constraints remain
first-class analytical records.

Examples:

- NO_DIRECT_PARENTAGE
- NO_DIRECT_RESPONSE_ANTECEDENT
- NOT_WITHIN_SECOND_TESTING_SCENE
- NOT_MEMBER_OF_CYCLE_1
- NO_BOUNDARY

They are distinct from:

- absence of an edge
- missing data
- QA negative controls
- unresolved relations

Contract must preserve:

negative assertion
≠
no record

--------------------------------------------------
R8 — Future overlays / append-only principle
--------------------------------------------------

ACCEPTED with qualification

Future:

- participant overlays
- rhetorical overlays
- lexical/responsio overlays
- other cross-layer analytical relations

may be appended without rewriting frozen lower layers.

However:

if new evidence genuinely requires changing a frozen lower-layer judgment,
this is NOT an ordinary overlay append.

It requires:

EXPLICIT_VERSIONED_SUPERSEDING_HUMAN_ADJUDICATION

Historical record remains preserved.

No silent mutation.

--------------------------------------------------
R9 — Relation-layer-specific validation
--------------------------------------------------

ACCEPTED

Graph invariants and cycle validation must be
relation-layer-specific.

Examples:

STRICT/MACRO HYPOTACTIC hierarchy:
- directed cycle invalid
- daughter mother cardinality rules apply

PARATAXIS:
- reciprocal relation may be valid

COMPOSITION:
- membership/order validation separate

OVERLAY:
- long-distance crossings allowed

TECHNICAL_NAVIGATION:
- not part of analytical hierarchy validation

Do NOT run one universal cycle detector
over the heterogeneous graph and interpret all cycles equally.
